### 0.1 本文要回答的最难的两个问题（先给答案，详见 §1.2 / §4.4）

1. **HR 在街区中的存在形态？**
   → **HR 的摊位就是他的公司本身；HR 本人以「摊主替身」常驻摊位，但不以真人身份实时在场。HR 进入街区的方式是「访客模式」——以访客标记浏览，并定向探访「作品廊」。**
2. **求职者在街区里如何被 HR 看到？**
   → **求职者的空间不在招聘街区里，而在独立的「作品廊」场景；HR 不能浏览、不能排行、不能围观，只能在收到投递后或主动检索到某一个「地址」后定向进入一次。**

## 1. 双角色总览

### 1.1 两侧的第一任务、时间预算与成功指标

| | **求职者（C 端 · 永久免费）** | **HR（B 端 · 付费）** |
|---|---|---|
| 第一任务 | **30 秒内判断"这家值不值得去"** | **5 分钟内让我的参数被看见、且不被质疑** |
| 时间预算 | 首屏 3s → 定位 5s → 读参 10s → 参观 60s → 投递 15s | 建厂 5 分钟；发布后 24 小时内收到首次访问 |
| 核心成功指标 | 每会话 ≥ 1 次**有效投递**（"有效"= 同一家公司不重复计数） | 建厂完成率 ≥ 60%；发布后 7 日被访问率 ≥ 40%；"参观办公室"触发率 ≥ 30% |
| 失败定义 | 逛了 10 家却一家都没投 = 失败（说明读不懂，不是逛得不够多） | 建厂中途退出且未发布 = 失败（说明"参数→空间"这条链路没让人信） |
| 最大风险 | **被比较 / 被处刑** → §3.2.3 三条硬约束 | **画饼被拆穿** → §4.2 诚实降级 + §4.3 版本留痕 |
| 反向指标（越低越好） | 被同屏并排比较的次数（目标 = 0） | 参数修改后未留痕的次数（目标 = 0） |

> **指标选择的理由**：求职者的成功不是"逛得多"而是"敢投"——投了说明读懂了参数空间；HR 的成功不是"发了很多"而是"被看了"。两者都指向 §1.2 的分工：**读参数 = 求职者的事；被读到 = HR 的事**。

### 1.2 同一个街区里两类人如何共处（**本方案最关键的产品问题**）

#### 1.2.1 三条不对称原则

| # | 不对称 | 落地 | 对应 project.md |
|---|---|---|---|
| **A** | **对象不对称** | 求职者的对照物是**公司参数**（山/月/楼）；HR 的对照物是**作品**。**人不对人**。 | 3.3 永不并排 |
| **B** | **空间不对称** | 公司在**招聘街区**（四街 64 摊位）；求职者在**作品廊**（独立场景）。两者**从不并排出现在同一个视野里**。 | 3.3「求职者空间之间永不并排排名」 |
| **C** | **时间不对称** | 公司是**常设摊位**——参数一经发布即固定陈列；求职者空间是**有门牌的地址**——HR 主动敲门才进得去。 | 5.1 / 5.4 防博弈 |

#### 1.2.2 由此推出的四条硬结论

```
① 求职者的空间不在招聘街区里。
   → 街区是"公司广场"；求职者住在另一条巷子（作品廊）。
   → 收益：3.3 的"永不并排"从一条规则升级为**物理约束**（两个展位被转角+隔断隔开，
     同一视野内最多 1 个求职者展位）。规则靠自觉，物理靠设计。

② HR 的摊位 = 他的公司（不是"某个人的展位"）。
   → 摊位上的名牌写公司名 + 职位，不写 HR 姓名。
   → HR 本人 = 「摊主」，其视角是"我的摊位"，不是"我在街上"。

③ 求职者默认不站在街头被围观。
   → 街头的 NPC 是"人气"（project.md v1.2-5 第 4 条），不是"可被投递的候选人"。
   → 真人求职者的空间只在作品廊，且需"门牌"才会被 HR 定向访问。

④ HR 的浏览权是"定向的"，不是"全景的"。
   → HR 不能"浏览作品廊里所有求职者"（那等于排行榜）。
   → HR 只能：① 收到投递后进入 ② 在「我的」页检索到某一个后进入。
```

#### 1.2.3 共处的时间线（一次完整相遇）

```
求职者 ── 逛招聘街区 ──▶ 读到某摊位参数 ──▶ 点「参观办公室」──▶ 进 3DGS 空间
   │                                                                            │
   │ 投递（生成投递回执文本）                                                        │
   ▼                                                                            ▼
HR ── 收到投递（演示数据/产品期通知）──▶ 打开该求职者空间地址 ──▶ 点环绕作品 ──▶ 拾起看详情
```

**两条流永不相交于同一画面**。求职者看到的永远是"公司"，HR 看到的永远是"作品"。这就是"同一街区里两类人如何共处"的完整答案。

## 2. 首屏角色选择流程

> 视觉规格完全沿用 role-flow-visual-v1 §2（双龛预览舞台、两张角色卡、五重编码、Tab 序、对比度实测表）。本节只补**流程与状态**。

### 2.1 分流决策图

> **首屏默认焦点（总纲 §2.5 架构决策 · 2026-10-27 拍板）**
>
> **「直接逛招聘街区」是首屏的默认焦点按钮**——Tab 序第一位、Enter 直达、视觉权重不低于两张角色卡。「我是求职者」/「我是 HR」是另两个明确选项，但**不是默认项**。
>
> 理由：评审需在 15 秒内判断"这是个 3D 产品"，而**纯 SVG 选角色页在录屏第一帧无法自证 3D**。这样录屏第一帧是选角色、第二帧就是街区鸟瞰——**角色选择不是"3D 之前的一道门"，而是"3D 里的一个岔路口"**。此决策同时满足"首屏提供角色选择"与"一键直达 3D"两件事。
>
> ⚠️ **一处已纠正的事实**：`App.tsx` 的初始 mode 是 `'single'`（单公司展台），**不是招聘街区**。因此"当前首屏 3D 含量偏低、角色选择页的第一印象损失比预期小"是事实；**但结论不依赖它**——结论由上面那条"录屏第一帧要能自证 3D"独立支撑。

### 2.2 首次访问 vs 回访

| | 首次访问（无 `gc-role-v1`） | 回访（有 `gc-role-v1`） |
|---|---|---|
| 首屏 | 完整双卡 + 说明句 + 卖点 + 耗时提示 + 「直接逛招聘街区」 | **角色卡折叠为一张"上次身份"小条**（48 高，嵌在页面底部），主区直接进入对应模式 |
| 进入内容 | 停在首屏，等用户选 | 求职者 → 招聘街区；HR → 「我的」工作台（建厂进度 / 我的摊位 / 收到的投递） |
| 首屏是否加载 3D 资产 | **否 —— 始终零 3D 资产、零 WebGL 上下文**（v1.1 §2.2） | **否**（直接懒加载街区主场景） |
| 回退成本 | 选错 → 需走 §2.3 修正路径 | 随时切（顶栏头像菜单 → 「切换身份」） |
| 引导卡 | 首屏不出现（引导卡属于进入街区后，ui-system-v3 §5.5） | 直接进入街区才出现引导卡 |

> **为什么回访要折叠角色卡**：角色选择是**一次性决策**，重复询问是典型的"表单式骚扰"。折叠成一条小条并保留「切换身份」入口，是把选择权留在用户手上而不反复索取的平衡点。

### 2.3 误选后的修正路径（**必须无死路**）

| 误选场景 | 修正入口 | 代价 | 数据处理 |
|---|---|---|---|
| 求职者选了 HR | HR 卡第 1 步顶部提供「← 我其实是求职者」文字链 | 0 步 | HR 草稿保留，不丢失 |
| HR 选了求职者 | 求职者面板底部「其实我是来招人的 →」 | 0 步 | 求职者草稿保留 |
| 进了街区才发现 | 顶栏头像 → 「切换身份」（两卡平铺，带上次选择高亮） | 1 步 | 进度全部保留 |
| 抽屉里发现 | `Esc` 关闭抽屉 → 回到上一步（不是回到首屏） | 1 步 | — |
| 完全不想要任何身份 | 首屏「直接逛招聘街区」；进入后顶栏仍可回 | 0 步 | 匿名逛，进度只存本地 |

|---|---|---|---|---|---|
| **L0 公开** | 作品集缩略（受作品级隐私控制）、**期望薪资档位**、学历铭牌、行业/技能标签 | ✅ | ✅ | ✅ | ✅ |
| **L1 投递后可见** | 完整作品详情、期望薪资**精确值**、GitHub 能力场（地砖路 / 森林 / 光谱环）、作品原文 | ❌ | ✅ | ❌ | ✅ |
| **L2 私密** | 原始照片、对比篮内容、全部投递历史、被划掉的记录、草稿、外观参数 | ❌ | ❌ | ❌ | ✅ |

**L0 = 档位而非精确值**是本文对 project.md 3.2 方案②「默认只显示薪资区间档位」的直接落地：期望薪资公开的是 6 档（如 `20–30 万`），精确值需要求职者授权，HR 看到精确值必须已经收到投递。

**三条硬约束（不可让）**

| # | 约束 | 实现 | 验收 |
|---|---|---|---|
| **S1** | **求职者空间之间永不并排** | 作品廊 = **十二边形折角环廊**（R=16.0m，12 边交替为 6 展位凹龛 + 6 实墙隔断；v1.2 §7）；同一视野最多 1 个展位；**不存在"作品廊全部列表"** | **断言式核验**（不靠人眼）：360 条射线（6×5 展位对 × 4 关键点 × 3 机位）——任一机位 → 下一展位关键点**必须与隔断/内壁相交**。**几何才是承诺，雾只是冗余**（v1.2 §7.6） |
| **S2** | **不提供求职者的排行榜/推荐位** | 「我的」页有"我的档案"，**没有**"热门求职者"；导航器罗盘不列求职者 | 全站检索无"推荐/热门/排行 + 求职者" |
| **S3** | **非 OSS 从业者不被公开处刑** | `verified_enterprise_years` 渲染为"无亮砖但有路基"+「企业内贡献已验证」铭牌；**该展位不与有亮砖的展位处于同一走廊段**（排布规则：展位按 `verified` 分流到不同走廊弧） | 截图核验：非 OSS 展位路面不断裂、不缺段 |

> **S3 的关键补充**（Phase 1 未涉及）：仅"底色路基"还不够——**并排的暗路与亮路本身就是公开处刑**。因此展位在作品廊里必须**按是否 verified 分流到不同走廊弧**，让非 OSS 求职者的空间**根本不出现在有 OSS 数据的走廊段**。这是把"不并排"从画面级推到**编排级**。

**"暗路"在交互层的呈现（用户明确点名）**

```
求职者在「我的」→ 我的档案 → 能力场来源：
  ○ 用 GitHub 公开数据（推荐）
  ○ 我的代码不在 GitHub 上 → [ 申请企业内贡献验证 ]

  [ 申请企业内贡献验证 ]  → 流程（Demo 期为模拟，产品期接 HR 端确认）：
     1. 填「近 3 任雇主 + 岗位 + 起止年月」  ← 结构化，不自由文本
     2. 生成一段「验证请求」文本（可复制）→ 发送给该雇主 HR / 前同事
     3. 对方在「我的」→ 待验证确认 页面确认「确认其在本企业从业 X 年」
     4. 本人收到 → 地砖路亮起"底色路基" + 铭牌「企业内贡献已验证 · X 年」
     5. 空间呈现：无亮砖（不伪造提交数据）、但有完整路基 + 已验证铭牌
```

- **确认方可以是前雇主，也可以是熟人** → 不给非 OSS 者设置必须依赖前雇主的门槛。
- **确认只证明"年限"，不展示任何工作内容**（project.md 3.3「不出示代码」）。
- **不接受上传代码截图作为验证材料**（防止把"验证"变成新的可刷分项）。
- Demo 期：整条链路是**本地模拟**（申请人 → 切换到"验证方"视角确认 → 切回），但界面文案不谎称"已联系到企业"。

### 3.3 作品集上传与悬浮

#### 3.3.1 作品类型与 3D 载体

> 载体几何沿用 role-flow-visual-v1 §3.4.2（矩形 = 平面作品 / 方形 = 项目卡片 / 圆形 = 3D 作品），本文新增视频与文档两类并给出降级。

| 类型 | 3D 载体 | 几何 | 材质/内容 | 数量计入 |
|---|---|---|---|---|
| **图像**（UI / 插画 / 摄影） | 玻璃卡 | 0.62 × 0.44 × 0.02 m | `opacity .78`，图像作 `emissiveMap`，顶部 12% 内高光带 | 1 |
| **视频**（≤ 15 s，自动循环，muted） | 玻璃卡（内嵌 VideoTexture） | 同玻璃卡 | 首帧作封面；播放时替换贴图；**不可播则回落为封面帧 + 「▶」标记**（形状编码，不只靠图标） | 1 |

| **3D 作品** | 实体展台 | 玻璃圆台 Ø0.60 × 0.28 + 作品缩模 | 圆台 `opacity .62` + 接触阴影 | 1（占位更大） |

- **不贴脸上**（project.md 3.3）：作品**不做头顶图标**，做**环绕空间景观**。
- **形状即编码**：去色后仍能区分四类 → 满足 WCAG 1.4.1。

#### 3.3.3 隐私设置（三档 × 作品级 + 全局）

| 档位 | 谁能看 | 3D 中的表现 | HR 视角 |
|---|---|---|---|
| **公开** | 任何人 | 正常显示在环绕轨道 | 点开可见详情 |
| **仅 HR 可见** | 已投递的 HR | **轨道位保留一个空槽轮廓**（40% 透明度），不显示内容 | 点开显示「这件作品未公开」 |
| **私密** | 仅本人 | 完全不渲染 | HR 不可见（作品数也不计入） |

- **全局默认 = 公开**（"作品强制可见"是产品主张），但**私密件在上传时默认选中"仅 HR 可见"**，需用户主动改为"公开"。
- **"仅 HR 可见"的空槽轮廓不透露任何内容**（不缩略、不模糊残影、不显示文件名）→ 防止从轮廓反推内容。

#### 4.1.1 Step 1 认证的可跳过设计（**不强迫，但显示代价**）

```
┌──────────────────────────────────────────────────────────┐
│  企业认证                                                 │
│                                                          │
│  已认证的公司会在空间门口挂一枚「已认证」铭牌，            │
│  求职者在对比篮里会看到认证章。                            │
│                                                          │
│  未认证也能发布 —— 但摊位会挂「未认证」底牌，             │
│  且在对比篮里排在已认证之后。                             │
│                                                          │
│  [ 用企业邮箱认证 ]   [ 稍后再说 → ]                     │
└──────────────────────────────────────────────────────────┘
```

- **不认证不阻塞**（B 端最忌讳强制注册）。
- **代价可见**：「未认证」底牌 + 对比篮排序在后 → 激励而非门槛。
- **不做"认证 = 可信"的等价承诺**：认证只证明"这是一个真实存在的企业主体"，**不证明参数为真**（参数真实性是 §4.3.3 版本留痕 + 产品期数据飞轮的事）。

#### 4.1.2 Step 4 预览 = 强制质量闸门（product.md 4.3 第 4 步的"HR 自己先逛一遍"）

| 预览里的四个必看项 | 目的是让 HR 自己调低画饼浓度 |
|---|---|

| 看**下班日月**在自己头顶 | 知道"23:00 下班"在自己的摊位上是什么感觉 |
| 看**HR 自己被钱捆堆环绕** | 知道参数是"围着自己转"的 |
| 切到**求职者视角**看一眼自己的摊位（可选按钮「看看求职者看到什么」） | 知道自己摊位在 64 个里是否被淹没 |

- 「看看求职者看到什么」= 相机切到求职者的跟随机位 + 距离 18m 处 —— **不需要切换场景**，避免又一套状态机。

### 4.2 办公空间照片 → 3D 空间：通道无关的流程

> **v1.1 同步**：本节已从「三档诚实降级」改为 **v1.1 §4.1 的生成通道模型**。本文原设计的「浏览器本地指纹匹配到 4 套已生成 SPZ」**已撤回**——Phase 1 已把这条需求明确定为 `replay` 通道（预置真实产物 + W1–W6 时间轴），更诚实且零猜测算法。

### 4.4 HR 在街区中的存在形态（**明确答案**）

#### 4.4.1 结论

> **HR 的摊位就是他公司本身；HR 本人以「摊主替身」常驻摊位，但不以真人身份实时在场；HR 进入街区的方式是「访客模式」——以访客标记浏览，并定向探访作品廊。**

#### 4.4.2 四条理由

| # | 理由 | 展开 |
|---|---|---|
| **1** | **诚实** | 单机 + 无后端 = 没有在线状态。伪造"HR 在线"等于造第二个"画饼"。产品公理是**双向反画饼**——这条必须先对自己生效。 |
| **2** | **反羞辱** | 若 HR 能实时在求职者的空间里走动挑选，求职者空间立刻退化成**被围观的展台**，project.md 3.3 的"永不并排"名存实亡。 |
| **3** | **对象清晰** | 求职者的对照物应是**公司参数**（山/月/楼），不是某个人的好感。把 HR 拟人化，会让「投个简历」变成"讨好某个人"——这恰是招聘平台应该去掉的中间层。 |
| **4** | **成本与性能** | 64 摊位 + NPC 已在临界；实时多角色需要后端状态同步（明确不做，project.md 9.2「明确不做」）。 |

#### 4.4.3 摊主替身（stand-in）的可执行定义

| 维度 | 定义 |
|---|---|
| **外观** | Phase 1 §4.4 的 9 个真 HR GLB + 9 色西装池 + 5 发型池；**西装不含行业色**，行业色只落在胸前工牌 |
| **名牌** | 写「公司名 · 职位」，**不写 HR 姓名** → 摊位 = 公司，不是个人 |
| **动作** | 仅 idle 待机 + 呼吸；**不做行走、不响应搭话、不做"迎接玩家"的表演** |
| **点击响应** | 点击摊主替身 = 点击摊位 = 打开**公司名片卡**（不是"与 HR 对话"） |
| **语义** | 替身是"这家公司今天有人值班"的符号，不是那个人 |
| **缺席表达** | HR 离线时摊位照常营业——因为**公司是常设的，HR 才是那个会请假的人**。这条同时服务反羞辱：求职者不会因为"HR 今天不在"而觉得被冷落 |

#### 4.4.4 访客模式（HR 进入街区的方式）

```
HR 点「我的摊位」→ [ 以访客身份逛街区 → ]
   │
   ├─ 视觉：玩家 Avatar 戴一枚「访客」标记（HR 角色色描边环，非行业色）
   ├─ 顶栏下方常驻一条细提示条：「访客模式 · 你正在以 HR 身份浏览」
   ├─ 街区内容不变（公司摊位照常）
   ├─ 新增能力：作品廊入口高亮 + 「我的」页 → 「人才」标签可检索并进入某个求职者空间
   └─ 退出：Esc / 点提示条上的「退出访客模式」
```

> **访客模式有两个正交维度**（这是 Phase 2 对 v1.1 R3 的容器化落地，详见 §4.5.1）：
> - **身份**：求职者 / HR（首屏确定，**在街区里不可切换**）
> - **观察对象**：招聘街区（看公司）/ 某个求职者空间（看作品）
>
> Demo 期的观察对象是**写死的 1 个示例求职者空间**，产品期才需要「切换观察对象」控件（且只列有投递关系或检索命中的求职者）。

**访客模式的能力边界（防滥用）**

| 可以 | 不可以 |
|---|---|
| 自由逛招聘街区（看所有公司） | 浏览作品廊"全部求职者列表" |
| 从「我的」页检索到**某一个**求职者并定向进入 | 对同一求职者批量导出联系方式 |
| 进入后点击其作品看详情 | 看到其期望薪资精确值（除非已投递） |
| 在其空间停留并被计数 | 收到"谁来看过我"的实时通知（只在投递后才有回执） |

#### 4.4.5 求职者的投递如何触达这个 HR（无后端的诚实路径）

**三级递进**

| 级 | 机制 | Demo 期实现 | 产品期 |
|---|---|---|---|
| **L1 现场反馈** | 投递动画 + 摊位留痕 | 简历袋抛物线飞入钱山 + 地砖路亮一格 + 摊位绿章 + 「✓ 已投递」浮标（沿用 ui-system-v3 §5.4） | 同 |
| **L2 可携带回执** | 生成一段可复制的投递回执文本 | 「复制投递回执」→ 含公司名 / 岗位 / 参数摘要 / 求职者空间地址 / 时间戳 / 一个带 hash 的短链接（本地可解析） | 同 + 站内消息 |
| **L3 收到投递** | HR 侧工作台收到 | **演示数据**：HR 工作台「收到的投递」为预设脚本注入（演示时现场触发） | 后端投递 API + 通知 |

**投递回执状态机（求职者侧「我的」→ 投递回执）**

```
  已送达 ──▶ 已读 ──┬──▶ 婉拒（带可选理由标签）
                    ├──▶ 面试邀约（带可选时间槽）
                    └──▶ 待回复（默认态，超过 7 天）
```

| 状态 | 求职者看到的 | 反馈 |
|---|---|---|
| 已送达 | 投递卡片上「已送达」章 + 时间 | — |
| 已读 | 「已读」章 | 1 状态变化 |
| 婉拒 | 「婉拒」章 + 理由标签（可选：方向不符 / 薪资不符 / 岗位已关闭 / 暂无更多） | 1 状态变化；**不做**任何情绪化文案（不写"很遗憾"） |
| 面试邀约 | 「面试邀约」章 + 时间槽 + 「加入对比篮 / 记下」入口 | 1 状态变化 + 1 操作反馈 |

> **婉拒的措辞纪律**：不给差评、不给评分、不给"你不够好"暗示。只陈述状态 + 可选客观理由。理由标签是**结构化选项**（5.3 的"结构化强制"精神同样适用于负面反馈）。

#### 4.4.6 HR 自建摊位在街区里的位置

| | Demo 期 | 产品期 |
|---|---|---|
| 位置 | **十字路口中心柱的四个底座**（"新开张"区，最多 4 个自建摊位） | 任意街区的空位 + 行业筛选 |
| 理由 | 不动已验收的 64 摊位布局与四臂罗盘；中心最显眼 = "新开张"最强的叙事位 | — |
| 标记 | 摊位挂「新开张」立牌 + HR 角色色描边（不占用行业色） | — |
| 排序 | 新开张区在导航器罗盘**中心**显示一个小圆点计数（不改四臂结构） | — |

#### 4.5.1 R3 ·「HR 点击求职者作品集看详情」的承载方式

**裁定：承载方式 = 「作品廊中的求职者空间」（本文 §3.4.2 方案）。采纳 v1.1 推荐的「HR 视角」思路，但否决新增一个独立的"HR 视角漫游模式"入口，也否决"求职者做成街区 NPC 摊位"。**

**Demo 期的唯一入口 = E1（投递后回执）**，不做额外的模式切换器。

**三条否决理由（针对"求职者做成街区 NPC 摊位"）**

| # | 理由 | 展开 |
|---|---|---|
| **1** | **反羞辱：违反本文 §1.2.1 的空间不对称** | 求职者一旦成为街区里的可见摊位，就同时发生"求职者在逛街"与"求职者在被看"——**§1.2.1 的空间不对称（街区=公司广场 / 作品廊=求职者巷）当场失效**。project.md 3.3 要防的正是"求职者在公共空间被并排围观"，而 NPC 摊位就是**把围观制度化**。 |
| **2** | **语义污染：两种摊位同构** | 公司摊位 = HR 形象 + 悬浮三件套 + 门面；求职者摊位 = 人形 + 悬浮物 + 作品环绕。**载体结构几乎一样，但一个是"公司"一个是"人"** → 用户会误以为求职者是可投递的对象，或误以为公司是个人。违反"载体职责互斥"（ui-system-v3 §4.1 / §4.4 的职责切分精神）。 |
| **3** | **性能不可行** | 求职者的空间要装地砖路 + 作品森林 + 光谱环 + 8 件环绕作品 + 要价云 = 至少 5 个载体实例；64 摊位密度下每多一个求职者摊位就是 5 个 draw call × 数量，而街区红线是 **≤200 draw call**（Phase 1 §4.3.3 论证）。 |

**为什么也不新增"HR 视角漫游模式"这个入口**

| # | 理由 |
|---|---|
| **1** | **E1 已经完整覆盖了演示需求。** Demo 期只有一个示例求职者空间；演示脚本是"求职者投递 → 切到 HR 视角 → 工作台出现该投递 → 点进去 → 作品可拾起"。这条路径**本身就是完整的投递→回执闭环**，比"HR 凭空切换到一个陌生人"更能讲清产品逻辑。 |
| **2** | **避免术语膨胀。** 本文已登记 9 个新术语（附录 A）。再给"HR 视角漫游模式"单独命名，会与已定的「访客模式」形成两个近义模式——**这是最容易在 Phase 3 沟通中踩的坑**。 |
| **3** | **省下的是真金白银。** 一个"切换观察对象"的机制 = 一个顶栏/抽屉选择器 + 状态存储 + 切换转场 + 空态/错误态，而它服务的是一个**只存在于 Demo 里的演示装置**。 |

**产品期怎么做（现在就要把接口留好）**

产品期有真实多用户后，HR 确实需要"在多个求职者之间切换"。届时**不新增模式**，而是把本文的「访客模式」**加一个正交维度「观察对象」**：

| 维度 | 取值 | 切换位置 |
|---|---|---|
| **身份** | 求职者 / HR（已在首屏确定，不可在街区里切） | 首屏 |
| **观察对象** | 招聘街区（看公司）/ 某个求职者空间（看作品） | 访客模式提示条右侧「切换观察对象」44×44 控件 |

- 观察对象列表**只列有投递关系或检索命中的求职者**，**不列全部求职者**（否则又变成排行榜，违反 §3.2.3 S2）。
- 切换观察对象 = 一次**相机传送 + 场景淡出淡入**（复用街区传送的 0.4s ease-out），**不重载页面、不重置进度**。
- **接口预留**：Demo 期的观察对象是**写死的一个示例求职者空间**；Phase 3 实现时把"观察对象"抽成一个 `{ id, kind: 'street' | 'space', spaceId }` 的单值状态，**Demo 与产品期共用同一套代码路径**——这样 Demo 里跑通的那条链路就是产品期那条。

**Demo 演示脚本（本文写死，供录屏使用）**

```
① 求职者视角：上传照片 → 形象贴入 → 传作品集 → 进街区 → 逛摊位 → 参观办公室 → 投个简历
② 画面切到 HR 视角（顶栏头像 → 切换身份）：
     HR 工作台「收到的投递」出现刚才那一条（演示数据）
     → 点候选人 → 进入该求职者空间（作品廊）
     → 环绕作品可拾起 → 玻璃详情板滑出 → 看详情 → 归位
③ 回到 HR 侧：收到回执状态变化（已读 / 婉拒 / 面试邀约）
```

> 这条脚本**同时演示了需求 4 和整个双角色闭环**，且不需要任何"假装有第二个人"的界面元素。

### 5.1 HR 点击求职者作品集看详情

#### 5.1.1 入口在哪（**三个入口，按到达路径区分**）

| 入口 | 路径 | 场景 | 说明 |
|---|---|---|---|
| **E1 · 投递后回执** | HR 工作台「收到的投递」→ 点候选人 → 打开该求职者空间 → 点环绕作品 | 作品廊 / 访客模式的个人空间 | **主路径**。投递后 HR 才有 L1 可见权 |
| **E2 · 主动探访** | HR「我的」→ 「人才」标签 → 检索（技能 / 关键词 / 行业）→ 结果点选 → 打开空间 → 点作品 | 作品廊 | 次路径。检索结果**是地址不是排行榜**：结果只显示"姓名/昵称 + 技能标签 + 可探访标记"，**不显示任何排名、不显示评分** |

> **HR 在招聘街区里看不到求职者的作品**——这是 §1.2.2 结论 ④ 的直接后果。街区里 HR 只看到公司。
>
> **承载方式的正式裁定见 §4.5.1**：Demo 期**只有 E1 一条路径**（投递后回执 → 进入该求职者空间 → 拾起作品）。**不新增"HR 视角漫游模式"入口**，也**不把求职者做成街区 NPC 摊位**（三条否决理由见 §4.5.1）。E2 的"人才检索"在 Demo 期可先只放 1 条演示数据，与 E1 指向同一个示例空间。

#### 5.1.2 点击后 3D → 2D 的转场（沿用 Phase 1 §5.1.1 四段，不改时长）

| 段 | 时长 | 内容 |
|---|---|---|
| ① **拾起** | 0–320ms | 作品卡脱离轨道，沿抛物线飞向相机；始终 billboard；背景玻璃模糊 28px → 56px |
| ② **落位** | 320–560ms | 作品停在中心偏左；右侧滑出**作品详情板**（380 宽玻璃） |
| ③ **停留** | — | 详情板常驻；背景保持 56px 模糊 |
| ④ **归位** | 面板 180ms → 作品 320ms | 面板淡出；作品缩回原轨道位；模糊回 28px（600ms） |

#### 5.1.3 详情面板结构

#### 5.1.4 关闭与返回

| 动作 | 结果 |
|---|---|
| `Esc` | 详情板淡出 → 作品归位 → **回到进入详情前的相机机位**（不重置到摊位中心） |
| 点右上 × | 同上 |
| 点面板外空白 | 同上（点击空白穿透到 3D 场景的点击需先关闭面板） |
| 浏览器后退 | 关闭面板（历史栈推一层） |
| 移动端下拉把手 | 同 `Esc` |

**归位是"可逆"的铁律**：用户看完必须能**回到原样**，不能丢失上下文（ui-system-v3 §7.1 的可逆性原则）。

#### 5.1.5 权限校验（**在点击之前就校验，不靠隐藏**）

| 作品的隐私档 | HR 未投递时点击 | 系统响应 |

| 公开 | 可看 | 正常拾起转场 |

| 私密 | 不渲染 | 点击不到 |

> **校验必须在服务端（产品期）/ 本地状态（Demo）双侧做**：Demo 期靠 `localStorage` 的投递记录判定；产品期服务端二次校验——**前端隐藏不等于权限**。

沿用 Phase 1 §5.2.2，交互层补充：

|---|---|---|---|
| 地面网格 | 1 m 一格 | 只读 | 保留 |

| 求职者的任何信息 | 参观是单向的：求职者看公司，公司看不到求职者 |

#### 5.2.4 参观计数的定义（**防止误触刷数**）

> 沿用 project.md v1.2-5 第 2 条「室内停留时长 = 参观感数据」，但必须定义清楚，否则"点一下就退"会刷出假的参观数据。

| 判定 | 阈值 |
|---|---|
| **计为「已参观」** | 在空间内**累计停留 ≥ 8 秒** **且** 移动距离 **≥ 3 m** |
| **不计入** | < 8 s 或未移动（误触、误关） |
| 计数归属 | **公司级**（`visited: string[]`，lot id），不是次数；重复参观不重复计数 |
| XP | `已参观` 每家 +XP（沿用现有 `GameXpPerVisit`） |
| HR 可见性 | HR 只看到**聚合数**（"今天有 12 人参观过你的空间"），**不含任何个人信息**，且**参观不触发 HR 通知**（避免把"好奇"变成"骚扰"） |

> **"参观不触发通知"是一条刻意的设计**：参观 = 匿名好奇；投递 = 表达意向。若参观也通知 HR，HR 会被大量无关访问淹没，反而降低回执质量。

#### 5.2.5 退出后回到哪

| 项 | 规则 |
|---|---|
| 相机 | 回到**进入前的精确机位与朝向**（不是摊位中心） |
| 名片卡 | **保持打开**（保留上下文，用户可以直接投） |
| 摊位状态 | 绿章「已参观 ✓」+ 导航器对应行加 👁 状态图标（形状编码，非颜色） |
| HUD | 「已参观」计数 +1，XP 条推进（1 状态变化 + 1 辅助反馈） |
| 焦点 | 焦点回到名片卡的「投个简历」按钮（键盘用户的连续性） |

**降级总原则（对应 lessons.md 的工程纪律）**

| 层 | 降级 | 绝不 |

| 投递回执 | 回执列表项 → 展开 → 「查看候选人作品」 | `Enter` 展开 |

**全局键**

| 键 | 行为 |
|---|---|
| `1` `2` `3` | 招聘街区 / 对比 / 我的 |
| `Esc` | 关闭最上层浮层（抽屉 → 详情板 → 控制台 → 弹层） |
| `←` `→` | 在当前街相邻摊位 / 当前展位的作品之间跳转 |
| `Enter` | 打开当前选中对象（摊位 → 名片卡；作品 → 详情板） |
| `Tab` | 顺延；`Shift+Tab` 回退 |

### 8.2 屏幕阅读器朗读

- **首屏**：完全沿用 Phase 1 §2.6.1 的朗读顺序；预览龛 `aria-hidden="true"`。
- **3D 场景的统一策略**：3D 内容**不进入 SR**（它无法被朗读）。所有 3D 里表达的信息，都必须有一个**等价的 2D 出口**：
  - 街区 → 导航器「邻近摊位列表」是可读的文本列表（公司名 + 距离 + 状态）
  - 摊位参数 → 公司名片卡（`num` 26px 数值 + 文字标签）
  - 作品环绕 → 我的展位内的作品列表（可 Tab 遍历）
  - 办公室语义锚点 → 「空间标注」开关后，锚点列表以 `role="list"` 提供文本项
  - **SR 用户可完全不使用 3D 完成投递流程**（这是硬要求）
- **状态播报**：`aria-live="polite"` 区，用于「已投递」「已参观」「作品已加入」「生成完成」等状态变化；**错误用 `assertive`**。
- **3D 里的角色**：HUD / 名片卡 / 导航器用 `role="region"` + `aria-label`；罗盘 SVG `role="img"` + `<title>` + `<desc>`（desc 里写"你在互联网区，附近 3 家摊位"）。
- **数值朗读**：金额一律读「八十万」而不是「800000」（`aria-label` 覆写）；时间读「晚上十点半」。

### 8.3 触屏手势与点击传送的冲突解决

> 冲突本质：点击传送需要"点"，但用户也想旋转视角、拖拽作品。

| 手势 | 行为 | 冲突处理 |
|---|---|---|
| **单击**（< 250 ms，位移 < 10 px） | 传送 / 选中 | — |
| **长按**（> 450 ms） | 拖拽物体（作品排序） | 长按期间禁用传送判定 |
| **双指** | 旋转视角 / 缩放 | 双指开始时立即取消单指传送意图 |
| **单指拖动地面** | 不传送（防止误触） | 拖动 > 10 px 即取消传送意图 |
| **点作品**（< 250 ms） | 拾起/打开详情（移动端为原地放大 + 底部面板） | — |

- **移动端不做 3D 自由旋转作品**（Phase 1 §3.2.6 的拖拽旋转仅桌面；移动端改为「上一件 / 下一件」按钮）。
- 移动端第一交互仍是**点击传送**（project.md 4.5 铁律）；虚拟摇杆作为**用户主动开启**的补充。
