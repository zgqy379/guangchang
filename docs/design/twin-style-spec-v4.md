# 逛厂 3D 街区 · 玻璃数字孪生风格规格 v4

> 版本：v4.0（2026-10-26）
> 决策：**风格定为「玻璃数字孪生 Glass Digital Twin」**，主题**白天浅色为主**，按**系统时间**自动切换夜间深色场景。
> 上游文档：`docs/design/ui-system-v3.md`（UI 厂玻璃）、`docs/design/art-style-options-v3.md`（10 方向选型，本文档是第 ⑨ 方向的深化）。
> 约束：距黑客松提交（2026-11-19 19:00）约 24 天；现有夜景资产需改造。

---

## 0. 决策摘要

| 项 | 决策 |
|---|---|
| 美术风格 | 玻璃数字孪生：半透明玻璃体块 + 线框网格 + 发光数据体 + 极简实体 |
| 默认主题 | **白天浅色**（建筑模型/沙盘质感，冷白玻璃 + 淡蓝天空） |
| 主题切换 | **按系统时间**自动：日出~日落 = 浅色，夜间 = 深色 |
| 环境时间 vs 参数时间 | **分离**：天色跟系统时间；公司"下班时间"参数仍驱动该公司的下班光效 |
| UI 玻璃 | **随主题反相**：浅色主题下用深色玻璃浮层，深色主题下用亮色玻璃 |
| 落地方式 | 新增 `theme.ts`（环境主题）+ 改造 `sky.ts`；材质与立面加"孪生化"通道 |

## 1. 为什么这个组合成立

### 1.1 「玻璃数字孪生」反而让白天切换更便宜

原本担心的问题：现有立面是**深色夜景贴图**（`facadeTexture()` 画的是深蓝底 + 暖色窗格），白天要用就得重做。

但玻璃数字孪生风格恰好绕开了这一点：

- 孪生体的核心是**半透明玻璃 + 结构线框**，不是"深色实体 + 亮色窗"
- 玻璃体在白天呈现**冷白 + 淡蓝天空反射**，在夜晚呈现**深靛 + 内部数据发光**
- **同一套几何体、同一套材质参数，只需切换环境色与自发光强度**

也就是说：需要改的不是"重做资产"，而是**给现有几何体换一套渲染通道**——这比重新生成贴图便宜得多，也保住了 64 摊位的已有布局与资产。

### 1.2 与产品定位的契合度最高

project.md 的立意是"**参数空间化 3D 求职招聘街区**"，v1.2 强调"作品即空间……空间风格 = 作者审美，这本身就是最诚实的简历"。

玻璃数字孪生是这个立意的**视觉直译**：

| 产品要素 | 孪生体的表现 |
|---|---|
| 参数（年薪/五险/期权/下班） | 悬浮的**发光数据体**，高矮粗细即数值 |
| 64 家公司 | 64 个**半透明玻璃体块**，形态各异 |
| 办公室（3DGS 实景） | 孪生体内部的**点云投影** |
| 求职者 | 街区中的**实体小人**（唯一的实体参照物） |
| 对比 | 两块孪生体并排，参数差直接可见 |

**这比任何一种"氛围向"风格都更准确地表达"这是个数据产品"。**

### 1.3 白天浅色的额外收益

- **评审场景友好**：白天截图在任何屏幕上都可读，投影仪、评委笔记本上不会糊成一片黑
- **手机端表现更好**：浅色底 + 深色字，户外强光下仍可读
- **与液态玻璃 UI 同源**：UI 的通透玻璃和场景的玻璃体块是同一种材质语言，形成整体感
- **符合"真实感"**：求职是严肃的事，白天招聘会更可信（赛博朋克夜景反而显得轻浮）

### 1.4 必须承认的代价

- **丢掉"深夜加班"的情绪表达**——但这是可接受的：情绪由**每家公司自己的下班时间光效**承担，而不是全局夜色
- **夜景资产需要改造**（立面、路灯、引导带），约 2–3 天
- **Aholo 3DGS 办公室是写实扫描**，与孪生风有割裂 → 缓解方案见 §6.3

## 2. 核心矛盾与解法

### 矛盾 A：亮玻璃 UI 压在浅色场景上会失效

**问题**：UI v3 方案的核心论据是"亮玻璃需要深背景才成立"，夜景街区上亮玻璃像悬浮舷窗。场景转浅色后，亮玻璃会消失在浅色背景里。

**解法：UI 玻璃随主题反相（不是改设计，是加一个变量）**

| 主题 | UI 玻璃 | 文字 | 场景背景 |
|---|---|---|---|
| `light`（白天） | **深色玻璃** `rgba(11,14,26,.72)` + 白字 | 墨色→反转为白 | 冷白玻璃 + 淡蓝天空 |
| `dark`（夜间） | **亮色玻璃** `rgba(255,255,255,.72)` + 墨字 | 保持墨色 | 深靛 + 发光数据体 |

实现上就是 CSS 变量的一组反相：

```css
:root {
  --glass-fill: rgba(255,255,255,.72);      /* dark 主题 */
  --ink-primary: #0b0e1a;
}
[data-theme='light'] {
  --glass-fill: rgba(11,14,26,.72);          /* light 主题反相 */
  --ink-primary: #e6edf3;
  /* 同理反相 --ink-secondary / --ink-muted / --glass-border / --glass-highlight */
}
```

> **注意**：这与 UI v3 §6.5 预留的 `data-scene-tone` 三态机制是同一套东西。落地时统一用 `data-theme`，取值 `light | dark`，替换掉 v3 文档里的 `dark | dusk | light`——**dusk 态在孪生风下由系统时间直接给出，不需要单独一态**。

### 矛盾 B：环境时间 vs 参数时间

**问题**：`offworkHour` 现在同时驱动天空——如果改成跟系统时间走，滑杆就失效了；如果保持原样，系统时间又没意义。

**解法：彻底分离两个时间语义**

| 时间 | 来源 | 驱动什么 | 语义 |
|---|---|---|---|
| **环境时间** | 系统时钟（`new Date()`） | 天色、太阳/月亮位置、环境光、星空、UI 主题 | "现在几点"（观众的真实世界） |
| **参数时间** | `offworkTime` 滑杆（每公司独立） | 该公司门前的**下班光效**（日落辉光 / 夜间冷光）、参数碑顶灯 | "这家公司几点下班"（产品数据） |

关键：**天色跟系统走，但每家公司的"下班"由自己的参数发光表达**。

实现：
- `theme.ts` 输出 `envHour`（系统时间）→ 决定 `twin` 材质的环境色与太阳/月亮
- 每家 lot 的 `offworkTime` 决定门前那盏"下班灯"的色温与强度
  - `≤18:30` → 暖金日落辉光
  - `19–21` → 暮色橙紫
  - `≥21` → 冷蓝月光

> 这样"智造区 17:30 下班"的公司在正午也亮着暖金的光——**它说的是"这家公司的作息"，不是"现在几点"**。语义清晰且信息密度更高。

### 矛盾 C：玻璃体的"可读性"与"通透性"冲突

**问题**：完全透明的玻璃体块，64 摊位在鸟瞰时糊成一片，个体识别度反而更差（这是盲审重灾区）。

**解法：分层玻璃 + 强制剪影差异**

1. **玻璃不是全透明**：实体部分 `transmission` 感靠 `opacity .55–.72` + 高 `roughness` 差异实现，保留体块边界
2. **每个玻璃体顶部保留一段"实体头"**（不透明）：这是**剪影载体**——不同行业的顶冠形态必须不同（互联网=平顶+天线 / 金融=尖顶退台 / 智造=烟囱+水塔 / 文创=坡顶+阁楼）
3. **数据体永远不透明且自发光**：高对比的彩色数据体块是画面里的"信息锚点"，也是远距离识别点
4. **线框网格叠加**：地面 + 建筑体加淡青线框，勾出结构

> 剪影差异是 v3 文档和检索结论反复强调的（"形状先于细节"），孪生风同样适用——**换成玻璃不改变这条规律**。

## 3. 视觉风格规格

### 3.1 白天主题（默认）

**天幕**
- 顶部 `#dfe9f2` → 中段 `#eef4f8` → 地平线 `#f7fafc`（冷白渐变，几乎无彩）
- 地平线附近一圈极淡暖光 `#fdf6ec`（避免纯冷显得像渲染器默认）
- **不使用星空、不使用月亮**

**太阳**
- 位置按**真实天文算法**算（参照检索到的 Jose and Goose 案例：经纬度 + 真实钟点 → NOAA/SunCalc 公式）
- 本项目用**用户本地时区**，纬度取 31.2°（上海附近）——"这是某个具体时刻的某个具体地方"
- 太阳本体：`#fff6e0` 圆盘 + 柔和光晕

**环境光**
- 半球光：天空 `#cfe4f5` / 地面 `#d8d2c8`，强度 0.85（白天高、夜晚低）
- 主平行光：暖白 `#fff2dc`，强度 1.8，**开启阴影**（4096 shadow map）
- 补光：冷蓝 `#9fc0e0`，强度 0.35，压暗背光面

**雾**
- `#eef4f8`，near 40 / far 190（比夜景更远，白天要通透）

### 3.2 夜间主题

- 天幕：顶部 `#0a1020` → 中段 `#111a30` → 地平线 `#1c2440`
- 星空：保留 `Stars`（count 1200）
- 月亮：`#e8edf5` 圆盘 + 冷蓝平行光 `#8fa8ff` 强度 0.75
- 半球光：天空 `#1a2440` / 地面 `#141018`，强度 0.32
- 雾：`#0d1424`
- **数据体的自发光强度在夜间 ×1.6**（夜里光更"跳"）

### 3.3 玻璃孪生体材质规格

| 部件 | 白天 | 夜间 |
|---|---|---|
| 玻璃体块 | `opacity .62`，`#cfe0ee`，`roughness .18`，`metalness .05`，淡青描边 `#7fb4d8` @ 0.5 | `opacity .55`，`#1a2740`，`roughness .22`，描边 `#4a9eff` @ 0.8 |
| 实体头（剪影） | `#e8eef4`，`roughness .75`，阴影接收 | `#1c2434`，`roughness .8` |
| 数据体 | 行业色，`emissive` 1.2，**不透明** | 行业色，`emissive` 1.9 |
| 线框 | `#8fb8d4` @ 0.18，白天更淡 | `#4a9eff` @ 0.28 |
| 地面 | 浅灰 `#dfe3e8` + 细网格线 | 深灰 `#141a26` + 网格线 |

### 3.4 品牌色的位置

品牌红 `#FF5A3C` 与金 `#FFD24A` 在孪生风里的角色要重新定义（不能再是"深夜霓虹"）：

| 色 | 新角色 |
|---|---|
| 品牌红 | **"已投递"状态色** + 品牌重音（招牌、名牌卡左边条） |
| 品牌金 | **XP/进度色** + 参数碑顶灯 + 稀有度 S 章 |
| 四区行业色 | **数据体主色**（主光源身份，夜里最跳） |

> 白天底浅，四区行业色需要提亮度以保证可辨：`internet #4a9eff` 保留；`finance #d4a72c` 白天改用 `#c9922a`（原色在白底上偏淡）；`manufacturing #f0883e` 改 `#e8722a`；`culture #c678dd` 保留。

## 4. 系统时间 → 主题的判定规则

```ts
// 6:00–8:30  黎明
// 8:30–17:30 白天（主色）
// 17:30–19:00 黄昏（过渡，UI 仍走深色玻璃）
// 19:00–6:00  夜间（深色主题）
```

| 系统时间 | 主题 | UI 玻璃 | 天空 | 备注 |
|---|---|---|---|---|
| 06:00–08:30 | `light` | 深色玻璃 | 冷白微暖 | 黎明 |
| 08:30–17:30 | `light` | 深色玻璃 | 冷白 | **主色（默认）** |
| 17:30–19:00 | `light` | 深色玻璃 | 暖金渐变 | 黄昏，UI 不变（避免闪烁） |
| 19:00–06:00 | `dark` | 亮色玻璃 | 深靛 + 星空 | 夜间 |

**防闪烁规则（必须实现）**：
1. 主题判定**每 60 秒**检查一次，不是每帧
2. 切换时**延迟 3 秒**再应用（避免临界点抖动反复切换）
3. 切换过程 UI 玻璃用 **600ms 过渡**，不做硬切
4. 允许用户**手动锁定**主题（顶栏加一个小太阳/月亮图标），锁定后不再自动切换——评审演示时不能被系统时间打断

> 最后一条尤其重要：**评审在晚上看 demo，就必须自动是夜间**；但**录屏时想拍白天，就手动锁**。

## 6. 三个高风险点的处置

### 6.1 材质改造量被低估？（最大风险）

**问题**：64 栋办公楼当前用 `facadeTexture()` 的深色夜景贴图 + `MeshBasicMaterial toneMapped={false}`。要变白天玻璃幕墙，需要新的浅色贴图。

**处置**：**不改贴图，改用法**——

孪生风的玻璃幕墙不需要"窗格贴图"，需要的是**"淡色玻璃 + 结构分格"**。因此：
- 保留 `facadeTexture()` 但**新增孪生参数** `mode: 'day' | 'night'`（同一函数两套画法，缓存 key 加 mode）
- 白天版：底色 `#dfe9f2`、窗格改为**淡青玻璃块**（`#b8d4e8` 渐变）、分隔线更深、无暖光窗
- 夜间版：即现有夜景
- **这不是重做资产，是同一个函数加一个分支**（约 1 小时）

### 6.2 Aholo 3DGS 办公室与孪生风割裂

**问题**：4 套办公室是写实扫描（真实房间点云），放进孪生街区像"贴了张照片的模型"。

**处置（按优先级）**：
1. **弱化**：进入办公室时加一层**孪生叠加层**（线框 + 网格 + 参数标签），把写实点云"框"进孪生语境——这反而强化了"这是办公室的数字孪生"的叙事
2. **加"扫描中"状态**：加载时显示"点云扫描中…"+ 进度线框动画，明确它是数据而非实景
3. **暂不重做**：3DGS 资产重生成成本高（每套 652s + 4 套），且 24 天内优先级低

> 第 1 条其实是**加分项**：真实感点云 + 孪生线框 = "数字孪生"的教科书表达。

### 6.3 白天场景下"数据体"的可读性

**问题**：白天底色浅，行业色数据体若用发光材质会过曝、边缘糊掉。

**处置**：
- 白天用 `emissiveIntensity 1.2` + **深色描边**（`#0b0e1a` @ 0.3）保证边界
- 数字标签（总包/下班）用**深色底 + 白字**的小胶囊（白天场景中浮空标签要压住）
- 数据体底部投影（contact shadow）增强落地感

### C.3 实施中踩到并修复的三个坑

1. **`match` + `transitive` 误伤 number 令牌** —— 自定义 transform 用 `match: token => token.$type === 'shadow'` 时，Style Dictionary v5 会把 number 令牌也过一遍 transform，导致 `game.xp.*` 全变成 `"none"`，HUD 显示 **Lv.NaN**。
   - 修复：改用 `filter` 限定类型；并在 `tokens.config.mjs` 末尾加**构建后自检**（number 令牌必须是 number，否则 `process.exit(1)`）
2. **主题锁定不生效** —— `lockMode` 改了但 `theme` 只在 `pendingTheme` 变化时经 3 秒防抖才应用，手动锁定因此"点了没反应"。
   - 修复：手动锁定**立即** `setTheme`，只有跟随系统时间的自动切换才走防抖
3. **半透明玻璃的对比度不能按纯白/纯黑算** —— 玻璃会透出 3D 场景，真实底色是合成结果（夜间亮玻璃 ≈ rgb(188,189,192)，白天深玻璃 ≈ rgb(63,67,79)）。初版用 `#7a8494`/`#8b949e` 只有 2.04:1 / 3.12:1，均不达 AA。
   - 修复：重算三级文字色阶（夜间 `#39414d`/`#454c59`，白天 `#b7c2cc`/`#b0bcc8`），并写 `tools/check-contrast.mjs` 常态化自检
