# 逛厂 UI 设计系统 v3 ·「厂玻璃 Factory Glass」

> 版本：v3.0（2026-10-26）
> 范围：`web/src` 的 **UI 层整体重构**（App 外壳 / HUD / 名片 / 导航器 / 词典表单 / 反馈层）。
> 3D 场景与词典引擎**不动**；所有颜色仍以 `web/design/tokens.json` 为唯一来源。
> 配套可交互原型：`docs/design/prototype/gc-glass-v3.html`（双击即可打开，无外部依赖）。
> 配套令牌补丁：`docs/design/prototype/tokens-glass-v3.json`（可直接并入 `web/design/tokens.json`）。

### 原型怎么用

双击 `docs/design/prototype/gc-glass-v3.html` 用浏览器打开即可（纯静态，无构建、无 CDN 依赖）。

- **可点**：投递 / 加入对比篮 / 移除 / 交换 A-B / 参观 / 切换邻近摊位 / 点区名传送 / 齿轮开合演示控制台
- **底部「桌面 · 平板 · 手机」**切换三档视口预览
- 原型已通过真实浏览器验证：1440 / 900 / 390 三档零控制台报错、零横向溢出、无浮层重叠

## 1. 问题诊断（基于 10-26 现状截图与三轮盲审共性结论）

三轮盲审分数分别为 视觉 6.5 / 空间 6.1、6.0 / 6.0、5.5 / 4.5，未过 7 分门禁。三位评审的**共性问题**高度一致，与我对照 `hero.png` / `focus.png` 实拍的判断吻合：

| # | 现状病灶 | 证据 | 本方案对策 |
|---|---|---|---|
| P1 | **演示形态与产品导航混淆**：顶栏把「逛一家 / A-B 对比 / 办公室漫游 / 招聘街区」四个 Demo 形态平级并置，用户找不到"我现在在哪个世界、能去哪" | `hero.png` 顶栏四按钮等权重 | 顶栏只留**产品级导航**（招聘街区 / 对比 / 我的）；Demo 形态收进右下**可折叠演示控制台**（§4.2） |
| P2 | **核心数值不可读**：名片卡里"总包 80万 · 下班 22:30 · 基数0.6"挤在一行 13px 文本 | `focus.png` 左下名片卡 | 拆成**三块数值瓷砖**，主数值 26px 等宽数字（§8.3） |
| P3 | **信息重复**：HUD 计"收藏"、名片按钮叫"对比"、顶栏又叫"A/B 对比"——同一件事三个名字；HUD 与名片同时展示行业标签 | `focus.png` 左下 + 右上 | 统一术语表（§5.3）；HUD 与名片**职责互斥**（§4.1） |
| P4 | **反馈过载**：一次投递产生 toast + XP 上浮 + 卡片绿章 + 摊位光变色 = 4 处 UI 反馈 | 盲审原文"一次投递有 4 处反馈" | 收敛为 **1 主反馈 + 1 辅助反馈 + 1 世界反馈**（§7.3） |
| P5 | **小地图装饰性强于导航性**：圆形 SVG 只画四街色臂与摊点，无距离、无排序、无未投递态、无点击直达 | `hero.png` 右下 | 重做为**罗盘 + 邻近摊位列表**的复合导航器，带距离、状态、可直达（§8.7） |
| P6 | **深色实心面板压在深色夜景上**，HUD 与名片区糊成一块，层级靠边框而非明度 | 全部截图 | 全量改**亮色液态玻璃**，靠模糊 + 内高光 + 双层阴影建立厚度（§6.2） |

> **P6 是本方案最大的视觉杠杆**：现有 UI 是"深底深字"，新 UI 是"亮玻璃深字"。在夜景街区上，亮色玻璃像悬浮的舷窗，天然成为视觉焦点，同时把对比度从"勉强"提到"优秀"。

## 2. 目标用户与核心场景

### 2.1 双端用户与各自的第一任务

| 端 | 用户 | 第一任务 | 时间预算 | 设计含义 |
|---|---|---|---|---|
| C 端（免费） | Z 世代求职者 | **看懂一家公司值不值得去** | 3 秒读懂 | 数值必须脱离氛围独立成层；行业标签一眼可辨 |
| B 端（付费） | 企业 HR | **让我的参数被看见、且不被质疑** | 5 分钟建厂 | 词典表单要可信：参数 → 空间映射的"感知说明"必须与控件同屏 |

### 2.2 求职者的四个真实场景

| 场景 | 心理 | 对应设计 |
|---|---|---|
| ① **随机逛**：下班路上随手打开，想看看行情 | 无目的、图新鲜 | 鸟瞰一眼看到四区景气差异 → 小地图/罗盘给"该往哪逛" |
| ② **定点看**：朋友推荐了某公司 | 有目标、要确认 | 名片卡 3 秒读出总包/下班/基数 → 一眼判断是否跑一趟 |
| ③ **横向比**：两家都说自己好 | 决策焦虑 | 对比篮 A/B 位常驻 → 双参数同屏 → 差值高亮（沿用 5.4 防博弈规则） |
| ④ **投递决策**：想投但怕画饼 | 怕被坑 | 名片卡上的**声明值 vs 感知值**并排（山高/月亮位置）+ 底部"这份参数如何被验证"入口 |

### 2.3 使用环境（决定了玻璃参数）

- **单手竖屏、通勤、户外强光** → 触控目标 ≥44px；玻璃需抗眩光（内高光 + 足够不透明度）
- **暗夜街区为主场景** → 亮色玻璃在深背景上不刺眼，反而聚焦
- **下班时间滑杆会改变天空**（黄昏 ↔ 深夜）→ UI 必须**场景自适应**（§6.5）

## 4. 导航逻辑

### 4.1 两级导航 + 一条快捷路（对齐虚拟招聘会通行范式）

```
L1 分区（十字路口四街）──► L2 摊位（街两侧 16 个）──► L3 详情（名片卡 → 抽屉）
        ▲                        │                        │
        └──── 罗盘/区进度行直达 ───┘◄──── 点击摊位直达 ────┘
```

**职责切分（解决 P3 的核心）**：

| 浮层 | 只回答一个问题 | 绝不重复 |
|---|---|---|
| 顶栏 | 我在哪个世界 / 能去哪 | 不显示任何参数 |
| HUD（右上） | **我的**进度如何（Lv / XP / 投递 / 对比篮 / 四区收集） | 不显示任何单家参数 |
| 名片卡（左下） | **这一家**怎么样（数值 + 动作） | 不显示等级进度 |
| 导航器（右下） | **我在哪 / 附近有什么 / 怎么过去** | 不显示数值排行 |

### 4.2 演示控制台（形态切换的收纳位）

- 位置：右下角导航器上方的一个 **⚙ 圆形按钮**（44×44），点击从右侧滑出 280px 抽屉
- 内容：逛一家 / A-B 对比 / 办公室漫游 / 招聘街区 / ▶ 生长动画 / 🚶 漫游模式
- 默认收起；收起时仅留一个带极弱脉冲的齿轮点（提示存在，但不抢戏）
- 明确标注「演示形态切换 · 正式版将移除」——避免评审误读为产品功能

### 4.3 跨模式状态保持（沿用 localStorage 铁律）

`delivered / visited / basket` 已通过 `gc-street-progress-v1` 持久化。新方案沿用，并把**对比篮内容也纳入持久化**（`gc-street-basket-v1`），避免切到对比页再回来篮子空了——这是当前实现的真实缺口。

### 4.4 键盘与无鼠标路径（WCAG 2.1.1）

| 键 | 行为 |
|---|---|
| `Tab` | 顶栏 → HUD（可聚焦控件）→ 名片卡 → 对比篮坞 → 导航器 → 演示控制台 |
| `1` `2` `3` | 切 招聘街区 / 对比 / 我的 |
| `Esc` | 关闭抽屉 / 控制台 / 名片详情 |
| `←` `→` | 在当前街的相邻摊位间跳转（导航器同步高亮） |
| `Enter` | 打开当前选中摊位的名片详情 |

## 5. 关键任务流程

### 5.1 主流程 · 逛 → 看懂 → 投递（不超过 3 步到投递）

```
进入街区（鸟瞰 2s 动画）
   ↓  [鸟瞰结束自动进入跟随视角]
   ▼
① 定位：罗盘指北 / 四区进度行显示"哪区摊位未投递最多"
   ↓  点区名 或 点罗盘臂  →  相机传送（0.4s ease-out）
   ▼
② 读参：接近摊位 → 自动 3/4 特写 → 左下名片卡淡入（180ms）
   ├─ 三块数值瓷砖：总包 / 下班 / 缴费基数
   ├─ 稀有度章 S/A/B（总包档位）
   └─ 行业色左边条
   ↓  [主操作「投个简历」常驻最左]
   ▼
③ 决策：投 / 对比 / 参观
   ├─ 投 → 主反馈 + toast + 世界留痕
   ├─ 对比 → 进入对比篮坞（A/B 位）
   └─ 参观 → 转场进 3DGS 办公室
```

### 5.2 对比流程

```
对比篮收集（任一摊位）
   ↓  篮满 2 家 → 对比坞按钮亮起（呼吸描边）
   ▼
进入对比页 → 双屏同参数并排
   ├─ 滑杆联动（改一侧两侧同步）
   ├─ 差值高亮（沿用 project.md 5.4：≥10× 夸张 + 数字标注）
   └─ 底部「换一家 / 清空」
```

### 5.3 状态机（单个摊位的完整生命周期）

```
        ┌──────── 未接触 ────────┐
        ↓                        │
   靠近(≤18m) → 已聚焦(名片浮出) │  已投递后仍可聚焦
        ↓                        │
   收藏 → 对比篮 A位/B位 ────────┤
        ↓                        │
   投递 → 已投递（不可重复投递）─┘
        ↓
   参观门面 → 已参观（+5 XP）
```

**状态在 UI 上的编码（不可只靠颜色，WCAG 1.4.1）**：

| 状态 | 编码 |
|---|---|
| 已投递 | 按钮变「已投递 ✓」+ 卡片右上绿色对勾章 + 摊位绿色信标（三重编码） |
| 已加入对比 | 按钮变「已在对比篮 A」+ A 位字母标记 |
| 未投递 | 摊位点为实心色点；已投递为对勾点 |

### 5.4 投递流程（含反馈收敛，对齐 P4）

| 时刻 | 反馈 | 层级 | 时长 |
|---|---|---|---|
| 点击瞬间 | 按钮按下态（scale .96 + 阴影收紧） | 触感层 | 80ms |
| T+0 | **主反馈**：按钮态 → 「已投递 ✓」+ 卡片绿章 | UI 主 | 200ms |
| T+0 | **世界反馈**：3D 摊位光变绿 + 「✓ 已投递」浮标 | 场景 | 1.2s |
| T+80ms | **辅助反馈**：右上 toast「已投给 星链科技 · +10 XP」+ HUD XP 条推进 | UI 辅 | 2.2s |
| T+80ms | XP 数字上浮 `+10` | UI 辅 | 900ms |

> 合并了旧版"4 处反馈"：现在 **UI 层只有 2 处**（卡片状态 + toast/XP），第 3 处属场景层不计入。旧版的"独立绿章 + 独立 toast + 独立 XP pop + 摊位光"现统一为一次投递事件的三段式。

### 5.5 新人路径（首访 ≤ 10 秒理解产品）

首次进入（localStorage 无 `gc-onboard-v1`）：

1. 鸟瞰 2s → 顶部居中**单句引导卡**：「四面街区，每家一个摊位。走近看参数。」
2. 自动跟随相机落地到互联网区最近摊位 → 名片卡淡入作为**教学样本**
3. 第二次点击任意摊位后，引导卡不再出现（写入 localStorage）

## 6. 视觉风格

### 6.1 风格定位

**「厂玻璃 / Factory Glass」**——通透的液态玻璃 + 品牌红金的夜间工业感。

不是 Apple Liquid Glass 的直接模仿：苹果的玻璃服务于浅色生产力界面；本项目服务的是**暗夜街区 + 强数值 + 游戏化进度**，因此玻璃取"通透"而取"轻"，用**亮玻璃 + 深墨字 + 品牌色发光描边**的组合，在夜景上建立最强的可读性与聚焦感。

### 6.2 玻璃配方（核心资产）

```css
.glass {
  background: linear-gradient(
    180deg,
    rgba(255, 255, 255, 0.82) 0%,
    rgba(255, 255, 255, 0.70) 48%,
    rgba(255, 255, 255, 0.60) 100%
  );
  backdrop-filter: blur(28px) saturate(180%);
  -webkit-backdrop-filter: blur(28px) saturate(180%);
  border: 1px solid rgba(255, 255, 255, 0.55);
  border-radius: 20px;
  box-shadow:
    /* 顶部 1px 内高光——玻璃厚度感的关键 */
    inset 0 1px 0 0 rgba(255, 255, 255, 0.85),
    /* 近距柔和影 */
    0 2px 6px -2px rgba(11, 14, 26, 0.28),
    /* 远距投影 */
    0 12px 32px -10px rgba(11, 14, 26, 0.45);
}

/* 顶部一道极淡品牌色扫光（品牌识别，成本 1 个伪元素） */
.glass::before {
  content: '';
  position: absolute; inset: 0;
  border-radius: inherit;
  background: linear-gradient(115deg,
    rgba(255,255,255,0.42) 0%,
    rgba(255,255,255,0) 38%,
    rgba(255,255,255,0) 70%,
    rgba(255,255,255,0.16) 100%);
  pointer-events: none;
}
```

**关键点**：玻璃厚度不靠"更透明"获得，靠 **模糊 + 内高光 + 双层阴影** 三者叠加获得。这正是浏览器里能做出可信玻璃的最小成本组合。

### 6.3 色彩系统（在现有令牌上扩展）

| 角色 | 值 | 用途 | 对比度 |
|---|---|---|---|
| 墨色（玻璃上的正文） | `#0B0E1A` | 主文字 | on 白玻璃 ≈ 19.6:1 ✓AAA |
| 次级文字 | `#4A5160` | 说明、标签 | ≈ 7.4:1 ✓AA |
| 品牌红 | `#FF5A3C` | 描边、发光、指示、图表 | 装饰用 |
| **品牌红深（主按钮底）** | `#C23A2B` | 实心按钮底 + 白字 | **5.41:1 ✓ AA** |
| 品牌金 | `#FFD24A` | XP / 进度 / 强调 | 配墨字 13.4:1 ✓AAA |
| 行业四色 | 互联网 `#4A9EFF` / 金融 `#D4A72C` / 智造 `#F0883E` / 文创 `#C678DD` | 色点、色条、边框 | **仅作色块/描边，不配白字** |

> **可访问性硬约束（必须写进 code review checklist）**：
> - 实心红按钮**必须**用 `#C23A2B`，**禁止**用 `#FF5A3C` 配白字（仅 3.10:1，不达 AA）
> - 行业色**禁止**承载白字（互联网蓝配白字仅 2.76:1）
> - 金色 `#FFD24A` **禁止**配白字，必须配墨字

### 6.4 字体与字号阶梯（正面解决 P2）

中文字体栈：`'PingFang SC', 'Microsoft YaHei', system-ui, -apple-system, sans-serif`
数字字体：`font-variant-numeric: tabular-nums`（关键：金额与时间必须等宽对齐）

| 令牌 | 尺寸/行高 | 字重 | 用途 |
|---|---|---|---|
| `display` | 30 / 38 | 700 | 大标题 |
| `2xl` | 24 / 32 | 700 | 抽屉标题 |
| `xl` | 20 / 28 | 700 | 名片公司名 |
| `lg` | 16 / 24 | 600 | 区块标题 |
| `md` | 14 / 22 | 400 | **正文默认** |
| `sm` | 13 / 20 | 500 | 次级正文、按钮 |
| `xs` | 12 / 18 | 500 | **仅限图例/徽章**，禁止承载关键数值 |
| `num` | 26 / 28 | 700 | **核心数值**（总包 / 下班 / 基数） |

> 旧版把"总包 80万"塞进 13px 文本行，是最伤专业感的细节。新版核心数值一律 `num` 26px，且**独占一块瓷砖**。

### 6.5 场景自适应（天空会变，UI 也要变）

`WorkdaySky` 由下班时间滑杆驱动，天空从黄昏到深夜。UI 玻璃随场景亮度微调：

| 场景 | `data-scene-tone` | 玻璃调整 |
|---|---|---|
| 夜晚（≥20:00）/ 默认街区 | `dark` | 标准亮玻璃（白 0.82→0.60） |
| 黄昏（18:00–20:00） | `dusk` | 顶部加深 6%（防橙色背景吃掉白玻璃边缘） |
| 明亮/办公室 3DGS 室内 | `light` | 切**深玻璃**变体（`rgba(11,14,26,0.72)` + 白字），避免白玻璃消失在亮墙前 |

切换由 3D 层上报 `sceneTone` 状态，壳层写 `document.documentElement.dataset.sceneTone`。**阈值取自天空组件的实际曝光参数，不另设魔法数。**

### 6.6 空间与圆角

- 间距基数 **4px**，刻度：4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48
- 圆角：卡片 `20px`、面板 `24px`、控件 `12px`、瓷砖 `14px`、胶囊 `999px`
- 8px 栅格；桌面 12 列，间距 20px，最大内容宽 1440px

### 7.1 四类反馈的分工（不可混用）

| 类型 | 定义 | 例子 |

| **引导反馈** | 表达"往哪走" | 罗盘高亮、区进度行、地面引导带 |

### 7.2 Toast 规范

- 位置：顶栏下方居中（不遮 HUD，不遮小地图）
- 样式：亮玻璃胶囊，图标 + 短句，右侧可带 XP 徽章
- 时序：进入 220ms → 停留 2200ms → 退出 180ms
- 同类消息 1.5s 内合并（如连续投递 3 家 → "已投递 3 家 · +30 XP"）
- 错误类（红边）停留 3200ms

### 7.3 加载态

- 街区首屏：品牌化遮罩（现有实现保留），文案「招聘街区搭建中，即将开门…」
- **禁止长时间白/黑屏无提示**：任何 >1s 的等待都要有骨架或进度
- 名片卡加载：骨架屏（灰色瓷砖占位），不显示 0 值

### 7.4 空态 / 错误态 / 首次态

| 态 | 文案 | 操作 |

### 9.2 移动端专项（Z 世代 70% 分享在手机）

- 横屏：导航器与名片卡改为左右两侧，避开中缝

### 9.3 缩放与文本放大

- 根节点 `font-size` 锁 16px，所有尺寸用 rem（例外：1px 描边、玻璃模糊半径）
- 200% 文本放大时：数值瓷砖允许换行而非溢出；导航项允许收缩为图标 + tooltip

### 9.4 原型实测得出的三条布局铁律

> 以下三条来自 `prototype/gc-glass-v3.html` 的真实浏览器渲染验证（1440 / 900 / 390 三档），**不跑真实渲染必然踩**：

1. **同侧浮层必须共用一个 flex 栈**。演示控制台齿轮与导航器最初都用 `position:fixed; right:12px` 各自定位，齿轮直接压在导航器面板上。改为 `.nav-stack { display:flex; flex-direction:column; align-items:flex-end; gap:10px }` 包裹两者后彻底消除重叠——**右下的浮层数量会增长，不能靠各自的 fixed 偏移量手工避让**。
2. **移动端 HUD 与名片卡必须在垂直方向彻底分区**。二者都贴底时，HUD 的计数行会被名片卡盖住（实测 390px 下 HUD 底 712px > 名片卡顶，卡片覆盖计数）。解法：HUD 上移为**顶栏下方的横向胶囊条**（等级 + XP + 三计数一行排布），名片卡独占底部，底部 Tab 之下。
3. **SVG 罗盘文字标签会被 viewBox 裁切**。区名放在 `x=8` / `x=123` 时，`getBBox()` 显示文字超出 132 视框即被裁。解法：标签内收到安全区（`x=19` / `x=113`），并把罗盘外圈半径从 58 收到 50 留出文字空间。

> 建议把上述三条做成 code review checklist 项：**新增任何 fixed 浮层前，先确认它与同侧已有浮层的 z 序与占位**。

## 13. 验收标准

### 13.1 功能验收

- [ ] 顶栏只出现产品级导航；形态切换仅在演示控制台内可见
- [ ] 核心数值（总包/下班/基数）渲染为 26px 数值瓷砖，不出现 13px 挤行
- [ ] 「对比篮」全站术语统一，无「收藏 / A/B 对比」混称
- [ ] 单次投递的 UI 反馈只有 2 处（卡片状态 + toast/XP），世界反馈 1 处
- [ ] 导航器可显示邻近摊位名/距离/状态，点击可直达
- [ ] 四区进度行可点击传送
- [ ] 对比篮内容跨模式持久化
- [ ] 375 / 768 / 1024 / 1440 四宽度下无重叠、无溢出、无横向滚动

### 13.2 视觉与可访问性验收

- [ ] 正文对比度 ≥4.5:1（用取色器复核白玻璃上的次级文字）
- [ ] 所有实心按钮均使用 `#C23A2B`（无 `#FF5A3C` 配白字）
- [ ] Tab 焦点环在玻璃上可见且有 2px 双环
- [ ] `prefers-reduced-motion` 下无位移/缩放动画
- [ ] 图标按钮均有 `aria-label`；SVG 有 `role="img"` + `<title>`

### 13.3 盲审门禁（沿用项目流程）

改造后须重新走**独立盲审**（只给截图、不告知实现），≥7/10 才放行。盲审重点提问：

1. 玻璃层在夜景上是否有"悬浮感"而非"贴片感"？
2. 数值是否第一眼可读（不再需要凑近读小字）？
3. 顶栏一眼能看出"我在哪、能去哪"？
4. 导航器是"地图"还是"指路牌"？

> 参照 `docs/design/design-audit-2026-10-25.md` 的门禁与留档流程。
