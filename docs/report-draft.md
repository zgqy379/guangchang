## 1. 问题概要

**招聘行业的核心矛盾：信息的表达方式（文字/数字）与人类的感知方式（空间/体积/光线）严重错配。**

"年薪 30 万""弹性工作制""快速发展中"——这些文字需要大脑翻译，而翻译过程就是"画饼"的生存空间。人类对空间量的感知是本能的、瞬时的、难以修饰的：一摞到膝盖的钞票和一人高的钞票塔之间的差距，不需要任何解释。

逛厂做的不是"把简历搬进 3D 场景"（形式 3D 化），而是**"把信息本身翻译成空间语言"（信息 3D 化）**：薪酬变成脚下真实比例的钞票山（15 万=15cm，100 万=1m），下班时间变成天空的夕阳或凌晨的月亮，期权变成半透明的"薛定谔钞票"。

## 2. 方案与差异化

- 竞品（Boss 直聘/虚拟招聘会/元宇宙办公）：信息仍是文字，3D 只是外壳
- 逛厂：**参数空间化词典**（`dictionary/*.json`，schema 化核心资产）定义"参数→空间"的映射规则；HR 面板表单由词典自动生成，加词条零前端开发
- 防博弈设计（词典 antiGaming 字段）：期权透明度上限 45%/缩放 0.5/视觉体积封顶 base×2；14/16 薪增量层强制异色；五险一金缴费基数→"切走部分"随档位缩放
- 双向反画饼：求职者的 GitHub 贡献变成发光地砖路（断更=断路），与 HR 的钞票山同框——"我的森林，换你的山"

### 3.1 关键资产迭代对比（报告硬性要求）

**迭代 A：钞票资产的"真钞→逛厂币"转向（最有故事的失败）**

| 版本 | prompt 要点 | 结果 | 存档 |
|---|---|---|---|
| v1 | Chinese 100 yuan banknotes（真钞主题） | ❌ provider status=4，疑似货币内容审核 | `lux3d-money/2026-10-25-v1` |
| 对照A | 金币堆（中性主题） | ✅ 107.8s，GLB 16MB | `lux3d-money/2026-10-25-gold-coins` |
| 对照B | fantasy banknote（虚构货币） | ✅ 107.2s，GLB 21MB → **逛厂币转正为视觉锤** | `lux3d-money/2026-10-25-fantasy-banknote` |

失败本身就是产品洞察：真钞可视化存在合规红线（与《人民币图样使用管理办法》预判互证），虚构币面成为主路径，Instanced Mesh 几何不变只换贴图。

**迭代 B：Avatar 风格锚定（同模板改单变量）**

三款文生 Avatar（基础/眼镜/马尾）截图并排（`lux3d-avatar/*/preview.png`）：Q 版卡通风格统一、结构完整无破面、单变量精确生效——批量生成的风格一致性前提成立。

**迭代 C：办公室双来源**

AI 生成（World SPZ 4.1MB）vs 真实扫描（InteriorGS 0024，工位信号最强场景）在 Aholo Viewer 中同屏可切换——"照片→空间"管线的两种形态对照。

## 4. 技术实现

- 架构：Vite + React 18 + R3F + drei（可视化）+ @manycore/aholo-viewer（3DGS，按需加载）
- 词典引擎：`dictionary/dictionary.schema.json`（DSL 含 antiGaming 字段）+ hr/candidate 双词典；HRPanel 由词典 JSON 自动生成
- 钞票山：Instanced Mesh 万级实例 + 金字塔逐层隆起生长动画 + 感知放大系数 2.5×（比例关系不变，15 万仍是 100 万的 15%）
- Avatar 漫游：点击行走 + WASD + 第三人称跟随相机 + Walk/Idle 交叉淡化
- 工程坑记录：aholo-viewer worker 与 Vite 预打包不兼容（optimizeDeps.exclude 解决）；Draco 解码器走 jsdelivr（国内可达）；provider status=4 偶发需重试
- 开源仓库：github.com/zgqy379/guangchang（含词典引擎，可复用）
- 在线 Demo：https://zgqy379.github.io/guangchang/
